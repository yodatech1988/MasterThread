# DayZ terrain workflow (from DayZ-Resources)

Synthesized from `DayZ-Resources/tools/dayz_tools/` (read-only source). Only what the sources state is included; gaps are listed at the end. Screenshots were not viewed; only filenames were used.

Sources (paths relative to `tools/dayz_tools/`):
- `DayZ_Tools_Overview.md` (DTO)
- `terrain_processor/Terrain_Processor_Overview.md` (TPO)
- `terrain_builder/Terrain_Builder_Overview.md` (TBO)
- `terrain_builder/Add_Objects.md` (AO)
- `terrain_builder/Bulldozer.md` (BD)
- `terrain_builder/buldozer.c` (BC)

## 0. Prerequisites (DTO)

1. Own DayZ on Steam; install "DayZ Tools" (Steam Library > Games dropdown > Tools > search "DayZ Tools" > Install).
2. Windows 10+ only; 8 GB RAM min (16 GB recommended), DX11 GPU 2 GB VRAM, 20 GB free disk, VC++ 2019 Redistributable.
3. Install DayZ and DayZ Tools on the same drive. If on a secondary drive, add it as a Steam Library Folder (Steam > Settings > Storage), then in DayZ Tools set Settings > Configure Path, and check drive Security permissions.
4. Mount the P drive: in DayZ Tools, Tools > Dismount Drive P if it needs a reset, then Tools > Workbench to mount P. Verify P appears in File Explorer.

## 1. Project layout (TBO)

Suggested top-level folders: `ce/`, `data/`, `navmesh/`, `source/`, `world/`.
- `source/`: `AllObjects/`, `images/` (`default_mask.png`, `heightmap.asc`, `satmap.bmp`, `normals.bmp`), `L3DT/`, `shapefiles/`, `TerrainBuilder/` (`.v4d`, `.v4w`, `.tml`), plus `layers.cfg` and `MapLegend.png` per the templates.
- `data/`: `config.cpp`, `layers/` (`M_000_000_lca.paa` / `.png`).
- `world/`: `config.cpp`, `CustomMap.hpp`, `CustomMap.wrp`.
- `navmesh/`: `config.cpp`.
- `ce/`: `db/` (`economy.xml`, `events.xml`, `globals.xml`, `types.xml`), `env/` (territory XMLs), `areaflags.map`, `cfg*.xml`.

Templates live in `terrain_builder/config_templates/` (`source/layers.cfg`, `source/MapLegend.png`, `world/config.cpp`, `data/config.cpp`, `navmesh/config.cpp`, `data/ce/...`).

Key input files: `heightmap.asc` (ASCII elevation grid, generated by "GQIS" and "L3DT"), `mask.png` (colors = terrain types), `layers.cfg` (maps mask colors to textures), `MapLegend.png` (visual legend of colors), `satmap.bmp` (satellite base texture), `config.cpp` (map size, grid size, etc.).

## 2. Ordered workflow

### Step A: Project setup in Terrain Builder (TBO "Setting Up Your Terrain Builder Project")
1. Prepare `heightmap.asc`.
2. Design `mask.png`; colors must match `layers.cfg` and `MapLegend.png`.
3. Edit `layers.cfg` to map mask colors to textures.
4. Define map size, grid size etc. in `config.cpp` (copy templates from `config_templates`, then update paths/parameters).
5. Put each file in `source`, `data`, `navmesh` or `world`.
6. Open Terrain Builder and load the project files.

### Step B: Configure Bulldozer (BD "Setting Up Bulldozer"), needed before any preview
1. DayZ Tools > Terrain Builder > Tools > Preferences... > "Buldozer" settings.
2. .exe path (example given): `D:\Steam\steamapps\common\DayZ\DayZ_BE.exe`
3. Launch parameters: `-buldozer -window -exThreads=0 -mod= -noAsserts -nologs -profiles=P:\Buldozer -cfg=P:\Buldozer\Buldozer.cfg -name=Buldozer`
4. Data directory: e.g. `P:\`
5. Optional script: see section 4.

### Step C: Object libraries (AO)
Option 1, prebuilt templates:
1. Clone `https://github.com/Treee/DayZDocs.git` (Git Bash: `git clone ...`).
2. Copy all `.tml` files from `DayZDocs\TemplateLibraryGenerator\output` to `MapName\source\TerrainBuilder\TemplateLibs`.
3. Terrain Builder > Library Manager > "load template library" > select all `.tml` > Open.

Option 2, manual:
1. Library Manager > Create New Library.
2. Name: leave blank (auto-generates); check "Create new library from directory"; Source Directory e.g. `P:\DZ\structures\roads\Parts`.
3. Set Fill Color, Outline Color, Shape (Rectangle or Ellipse).

### Step D: Roads/paths via Terrain Processor (TPO)
In Terrain Builder:
1. Layers Manager > new layer in the `Shapes` tab; keep it selected.
2. Polyline Tool: draw the feature (road/river/boundary); double-click the last point to finish. It shows in a distinct color (e.g. pink).
3. Selection Tool: click the polyline to check its properties (layer, name, position, colors).
4. File > Export > Shapes...: choose selection source, save path e.g. `MyCustomMap/source/shapefiles/customName.shp`; OK; a confirmation popup appears.

In Terrain Processor (open from DayZ Tools):
5. First time: create a new project named after the map, saved in `MyCustomMap/source/TerrainProcessor/` (create the folder if missing).
6. New line icon > select "Line: Regular".
7. Import the exported `.shp`; the polyline previews.
8. Objects tab: add an object (example `asf1`) that matches an object already imported in Library Manager. Use the ROTATION field if the object does not line up in Terrain Builder. Click OK.
9. Run "Execute Tasks". Output is a `.lbt` file.

Back in Terrain Builder:
10. File > Import > Objects...; select the Terrain Processor `.lbt` file.
11. A new layer appears in Layers Manager; rename it.
12. If objects are not in the Library Manager, an error says they are missing.

### Step E: Test in Bulldozer (TPO, BD)
1. Steam must be running (TPO). Click the Bulldozer icon in Terrain Builder.
2. Check that objects load per the values set in Terrain Processor.
3. Edit in Bulldozer using the keys below. TBO also says: use Bulldozer frequently, export often for backups, and optionally prototype object placement in the DayZ Editor then export to Terrain Builder.

Bulldozer keys (BD):

| Key | Function |
|---|---|
| F | Swap Brush Tool / Object Mode |
| R | Remove selected object |
| 5 | Hold to rotate (X-axis); also changes Object Mode function (Rotate / Scale / Elevate) |
| 3 | Hold to rotate (Z-axis) |
| G | Brush mode Smooth / Normal (Normal raises land) |
| 6 | Toggle Object / World coordinates |
| F10 | Run the custom script; BD also says it "improves visual quality" (only when connected to Terrain Builder) |

### Step F: Later stages named by the sources (not detailed)
Economy Editor is "typically the final step" (DTO). PBO packing: Addon Builder, with PboProject recommended (DTO, links to `../mikero_tools/Mikero_Tools_Overview.md`). Publisher uploads to Steam Workshop (DTO).

## 3. Why Terrain Builder over DayZ Editor (TBO, quoting Duncan via Discord)
TB objects are hard-coded into the map (lighter server start-up); Editor objects are added as scripts that spawn at start-up.

## 4. What `buldozer.c` is

`terrain_builder/buldozer.c` is an Enforce-script file defining `static void BuldozerMain()`. Its comments say the file name and method name depend on the `-name=` launch parameter (`buldozer.c` / `BuldozerMain` for `-name=Buldozer`, i.e. `<username>Main`), and that F10 runs it in Buldozer when connected to Terrain Builder. Active settings:
- terrain view distance 1500 (`SetViewDistance`); object view distance 1200 (`SetObjectViewDistance`)
- aperture 1 (`SetAperture`)
- weather: `wo.GetRain().Set(0, 0, 28800)`, same for Fog and Overcast; `SetWindMaximumSpeed(1)`; `SetWindFunctionParams(0.1, 0.1, 25)`
- date `SetDate(2020, 12, 25, 11, 0)`

Commented-out alternatives: `SetPreferredViewDistance(1500)` (saved to profile), `SetBuldozerWaterEnabled(waterVisible)`, date 1994-9-11 12:00, and a weather variant `Set(0, 28800, 0)`.

BD embeds the same content and says to save it at `P:\scripts\bulldozer.c`, then restart Terrain Builder and launch Bulldozer.

## 5. Glossary (as used by the sources)

- **P Drive**: mounted modding workspace/sandbox so game files are not altered (DTO).
- **Terrain Builder (TB)**: shapes terrain, places objects, previews in Bulldozer.
- **Bulldozer / Buldozer**: real-time preview tool run via `DayZ_BE.exe`; spelled both ways in sources.
- **Terrain Processor (TP)**: generates objects (roads, paths, etc.) from shapes; outputs `.lbt`.
- **Polyline**: line drawn in TB on a Shapes layer.
- **Shape file (.shp)**: export of the polyline for TP.
- **.lbt**: TP-generated object list imported into TB.
- **Library Manager**: TB panel for object libraries.
- **.tml**: template library files (`source/TerrainBuilder/TemplateLibs`).
- **.v4d / .v4w**: TB project files (only named in TBO).
- **heightmap.asc**: elevation grid. **mask.png**: terrain-type color map. **layers.cfg**: color to texture mapping. **satmap.bmp**: satellite base texture. **normals.bmp**: listed only.
- **.wrp**: world file (`CustomMap.wrp`).
- **PBO**: packed mod archive (Addon Builder / PboProject).
- **Economy Editor / ce**: loot, zombie, vehicle spawn config.
- **Workbench**: Enfusion engine tool; also used to mount P.
- **Object Builder (OB)**: 3D model tool; helps export P3D as FBX/OBJ.
- **Addon Builder / Publisher**: PBO packer / Steam Workshop uploader.

## 6. Gaps / unclear / contradictions

- **Script filename**: BD says the script must be `P:\scripts\bulldozer.c`, but `buldozer.c` comments say the name must be `buldozer.c` (from `-name=Buldozer`). Spelling differs; the repo file is `buldozer.c`. Unresolved which is correct.
- **Weather arguments**: the commented example says "clear, no rain, next change in 8hrs" with `Set(0, 28800, 0)`, but the active code uses `Set(0, 0, 28800)`. Sources do not explain argument order.
- **F10**: BD says it "improves visual quality for edits", BC says it runs the script. Presumably the same; not stated.
- **Keys 5 / 1 / 3**: the table says 5 rotates X-axis; the notes say `1` applies to X-axis and 5 changes the function. Inconsistent.
- **"Modification = Scale / Elevate"**: no keys or details given.
- **TP "Missing Fields Guide"**: TPO links it to `/DayZ_Resources_TODO_List.md` (outside the folder read; not verified). The field list is only in a screenshot.
- **TPO wording**: says to bring "exported data" back into TB, but the actual output is an `.lbt`. TPO lists batch processing, elevation adjustment and object distribution as features but gives no steps for them.
- **TPO's absolute link** `/tools/dayz_tools/terrain_builder/Terrain_Builder_Overview.md` may not resolve.
- **Object name `asf1`**: example only; naming rules for library objects are not stated.
- **No steps** for loading heightmap/mask/satmap into TB, creating the map/`.wrp`, generating layer textures (`M_000_000_lca.*`), or packing to PBO. TBO lists needed files but not how TB consumes them.
- **Bulldozer paths**: `D:\Steam\...` is a user-specific example; contents of `P:\Buldozer\Buldozer.cfg` not given.
- **"GQIS"** in TBO is probably QGIS; the source writes GQIS.
- **Steam must be running** for Bulldozer is stated only in TPO.
- Screenshots were not inspected, so details only in PNGs are not captured.
