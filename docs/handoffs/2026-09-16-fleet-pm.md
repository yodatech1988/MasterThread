## 4a. The single best explanation for the night's confusion

Verified by `git log`, not relayed. Commit `d8ce422` ("docs: PM-handoff usage policy, anti-polling
handshake, real-time telemetry") is real, committed, and authored by the owner's own account. It sits
on branch `agent/masterthread/fleet-pm-policies` — **never merged to `origin/main`, with no open PR** —
and that branch is what happens to be checked out in the single shared `GitHub\MasterThread` clone
that every session on this machine reads from.

So any session that read those files off disk was reading an unmerged branch's content as though it
were the adopted standard. No fabrication, no unauthorised edit, no malice anywhere in the chain — a
shared local checkout silently presented an unmerged branch as canonical to every session that read
it. That single fact accounts for most of the night's contradictory conclusions, including two
sessions reaching opposite verdicts about the same file.

This is why the verification rule "read `origin/<default>`, never a shared working tree" is first in
the structure document, and why it is worth more than it looks.
