# Contributing to MasterThread

Welcome to **MasterThread**, the unified AI-governed control plane for the entire ecosystem:  
DayZ GameOps • Discord Community • Patreon Entitlements • Engineering SDLC • Analytics • Business Automation.

This repository contains:
- Policies (“the laws”)
- Standards (“how work must be done”)
- Agents (“specialized workers”)
- Orchestrators (“executive-level controllers”)
- Workflows (“machine-readable operating system”)

Humans and AI collaborate **side-by-side**.  
This document explains how contributions work in a hybrid environment.

---

# 🔷 1. Contribution Philosophy

MasterThread is designed for:
- **Predictability** → every agent behaves deterministically.
- **Safety** → policies and standards prevent unintended actions.
- **Auditability** → every decision, mutation, workflow, and privilege change is logged.
- **Traceability** → every change maps back to an issue, workflow, agent, or policy.
- **Continuous Improvement** → both humans and AI extend the system.

Humans provide:
- Strategic decisions  
- High-level direction  
- Approvals for irreversible actions  
- Policy changes  
- Creative and social nuance  

AI provides:
- Execution  
- Automation  
- Analysis  
- Workflow orchestration  
- Documentation and testing  

Together, both humans and AI maintain this repo.

---

# 🔷 2. How to Request a Change

All changes begin with a **GitHub Issue**.  
Use one of these labels:

| Label | Purpose |
|-------|---------|
| `feature` | New functionality |
| `enhancement` | Improve existing behavior |
| `bug` | Something is broken |
| `policy-change` | Modify policies/standards |
| `agent-change` | Modify agent contracts or behavior |
| `workflow-change` | Modify automation logic |
| `docs` | Documentation changes |
| `ops` | GameOps or server operations changes |

AI Orchestrators automatically route issues through the SDLC workflows unless explicitly marked **“human-only”**.

# 🔷 3. Working With Agents

Every agent lives under `agents/<domain>/<agent_name>/`.

Agents contain:
- persona.md  
- responsibilities.md  
- io_contract.json  
- dependencies.md  
- escalation_rules.md  
- notes.md  
- examples/

To modify an agent:
1. Open an issue describing the change.  
2. Orchestrators will route it to the correct workflow.  
3. Most changes result in a pull request generated by AI agents.  
4. Humans may review and approve/deny.

**Never** manually adjust agent folders without following the SDLC workflow unless explicitly in “emergency hotfix mode.”

---

# 🔷 4. Working With Policies and Standards

The **policies/** and **standards/** directories govern all agents.

## AI may NOT:
- Change policies without a `policy-change` PR  
- Override standards without Governance approval  
- Apply entitlements or punishments against policy rules  

## Humans SHOULD:
- Review policy changes carefully  
- Approve or reject orchestrator-generated PRs  
- Maintain consistency across all domains

---

# 🔷 5. Working With Workflows

Workflows live under `workflows/<domain>/`.

These YAML files define:
- Triggers
- Stages
- Agents involved
- Input/Output artifacts

If you edit a workflow:
- The Architect or Orchestrator agents will validate it
- A simulation may run to check compatibility
- A PR must be approved by a human or Governance Orchestrator

---

# 🔷 6. Branching Model

We use a simple model:

- `main` → production-ready  
- `dev` → staging for new workflows/standards  
- AI-generated PRs ALWAYS target `dev`  
- Humans decide when to merge `dev` → `main`

Agents may not merge PRs into `main` unless:
- it is a fix for a broken workflow
- it passes governance checks  
- it has explicit human approval  
- the policy allows auto-merge under specific conditions

# 🔷 7. Code / YAML / Policy Reviews

AI reviewers (Code Reviewer, Design Reviewer, Governance Orchestrator) will:
- Add comments
- Suggest improvements
- Highlight risk
- Ensure compatibility with standards

Humans should:
- Focus on strategic, ethical, and safety considerations  
- Look for unintended consequences  
- Approve or request changes  

---

# 🔷 8. Testing and Validation

Test plans are generated and executed automatically by:
- Test Case Generator  
- Test Plan Executor  
- Automated QA Executor  

All PRs MUST:
- Pass tests  
- Meet standards  
- Align with policies  
- Maintain backward compatibility (unless a major version bump)

---

# 🔷 9. Human Responsibilities

Humans should:
- Set long-term direction  
- Approve sensitive changes (bans, big economy shifts, revenue changes)  
- Oversee fairness & safety  
- Update policies as the project evolves  
- Monitor the AI’s performance periodically  
- Provide guidance for ambiguous tasks  
- Validate assumptions AI may not detect  

---

# 🔷 10. AI Responsibilities

AI agents MUST:
- Follow workflows exactly  
- Respect policies and standards  
- Log every action  
- Escalate unclear or risky situations  
- Provide explainable outputs  
- Keep all data structured and predictable  

---

- Tag the relevant domain label  
- Ping the Architect or Governance Orchestrator  
- Or ask in the Discord support channel (routed by the Support Ticket Agent)
